# 运行保护

这些机制用于限制异常输入和失控运行，不能保证账号不会受到游戏处罚。没有通过随机点击、伪装设备或绕过验证来恢复受限账号。

## 默认生效

- 每次设备截图后、发送常规控制动作前检查违规通知。识别到后保存错误截图、通知并停止账号。
- 当前模板适配 1280×720，覆盖已采集的违规通知及通知被断线窗口遮挡的画面；其他分辨率和新样式尚未验证。
- 同一按钮触发底层点击过多保护后直接停止，不再自动重启。
- 卡住、未知页面、客户端异常退出等恢复操作，每个账号 30 分钟内最多允许一次。再次发生即停止；恢复记录不会因换任务或重启脚本而清零。
- 页面跳转连续失败三轮即停止；导航总超时也停止。战斗准备和等待阶段各最多重试三次。
- 爬塔挑战最多点击三次，总入场等待最多 30 秒，不再返回外层循环重新开始一轮重试。
- 已识别的本期神秘补给窗口只点击关闭，最多两次；未关闭就停止。入场遇到其他确认窗口也停止。

## 爬塔次数和资源

次数在首次点击挑战前预留，并持久化到账号独立的状态文件。异常、暂停、跨午夜和脚本重启都继续使用未完成的预算。正常结束后，下一轮任务才创建新预算。

预留方式是保守计数：一次未能确认进场的尝试也可能消耗一个名额，避免崩溃后重新获得完整预算。首次启用不能恢复旧版本未记录的已用次数。

活动道具读取三张截图。读数相差超过 5，或相较前次骤减超过 5，停止并保留现场。正常从 1 到 0 可结束任务；从 801 到 0 会停止复核，不再误报道具耗尽。此规则针对目前每次消耗一个活动道具的模式；新活动需重新适配。

## 作息设置

沿用 `Script → anti_ban` 的开关、睡眠窗口和活跃时长设置，默认配置不变。启用后，爬塔在每局之间及挑战前检查作息，达到条件后延后任务；不主动中断正在进行的战斗。其他任务仍在调度边界检查。

现有活跃时长统计仍为进程内统计，重新启动脚本会重置；它不是可跨进程审计的每日配额。配置名称中的“每日活跃上限”当前行为是累计达到上限后休息，再重新累计。异常停机记录和爬塔预算不受此限制，均已持久化。

## 查看和解除停机

先手动检查游戏页面、账号状态和 `log/error` 下的截图，处理原因后再解除。不要通过反复解除来绕过保护。

```powershell
.\toolkit\python.exe dev_tools/runtime_safety.py oas1
.\toolkit\python.exe dev_tools/runtime_safety.py oas1 --clear-stop
```

解除只清除停机和恢复记录，保留未完成的爬塔次数。状态位于 `config/runtime_safety/`，已加入 Git 忽略。更新代码后需要重启 OAS 进程生效。

## 验证范围

使用离线错误截图验证识别，并通过单元测试检查停机、恢复次数、导航重试、准备重试、预算恢复和资源异常。没有在受限账号上重新发起战斗。自动御魂清理调度仍需另行处理。
